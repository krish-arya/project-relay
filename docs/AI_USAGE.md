# AI usage

## Tools and models

| Tool | Model | Used for |
|---|---|---|
| Claude Code (VS Code extension) | Claude Opus 5.5 | Reading the brief, design, writing essentially all code, tests and docs, running the system and the evals, debugging. |
| Ollama (runtime, not a coding aid) | qwen2.5:1.5b, qwen2.5:3b, nomic-embed-text | The system's own models. |

No paid API was used by the system or to produce any committed result.

## How much was generated

Roughly 95%+ of the code and documentation was generated by the coding agent, working in small steps
with commits along the way (see the git history). Every number in `docs/EVAL.md` and every file under
`out/` and `eval/runs/` is real output of the code. None was written or edited by hand. The commentary
in `eval/NOTES.md` was written by hand and is marked as such.

## Where the assistant was wrong, and how it was caught

1. **Circuit breaker test expectation.** The first version of
   `test_breaker_opens_and_falls_back_to_second_model` assumed the breaker opens after the first failure.
   With a threshold of 2 it opens after the second. Caught by the test failing; the code was right and the
   test was fixed.
2. **RLS on the fingerprint table.** The test expected `SELECT` on `kb_fingerprints` to return zero rows. The
   app role has no grant at all, so Postgres raises `permission denied`. Caught by the test failing; the test
   now asserts the stronger behaviour.
3. **Routing for the bulk-order ticket (NW-T12).** The first routing gave an acknowledgement to any `other`
   ticket whose best KB score was high. The off-topic bulk-discount request scored 0.67 against the assembly
   article, so the agent would have drafted "thanks, we'll be in touch" to a sales lead. Caught by reading the
   demo approval queue, and fixed with an explicit rule: an `other` ticket that asks for something escalates.
4. **A hang hidden by a mutation test.** To check that the tests would catch a broken lease check, the
   assistant mutated `queue.complete`. The test suite then hung instead of failing: the worker waited forever
   on a job whose lease it had "lost". Caught by a stack dump. It led to the `max_idle_s` cap on
   `Worker.run_until_empty`. With the cap, the same mutation fails 6 tests cleanly.
5. **A silent no-op edit.** A `sed` command meant to fix a zero-width-character probe matched nothing
   (shell escaping). Caught because the follow-up `grep` count was 0; redone with a Python replace.
6. **Empty `kb_refs` and mixed-up drafts.** The first full demo looked fine in the approval-queue summary.
   Reading every draft in full showed three problems:
   - `kb_refs` was empty on most drafts, because the model cited `[NW-KB-01]` inline and left
     `cited_kb_ids` empty.
   - HD-T06 answered a root-canal price question with cancellation-fee text, because the drafter had been
     given three loosely related passages.
   - A wrong figure passed the checker.

   The fix: give the drafter only passages close to the best match, record inline citations, and add a
   checker rule that every number must come from a passage or the ticket.
7. **That number rule was too strict at first.** It escalated a correct HD-T06 draft that quoted "INR 600"
   from the only passage the drafter had seen but forgot to cite. Caught with `relay show HD-T06`, which
   prints the checker's reason. Numbers from passages shown to the drafter now count as grounded.
8. **Misleading threshold.** The first assumption was that `RETRIEVAL_MIN_SCORE` would separate covered from
   uncovered requests. Printing the scores showed nomic-embed-text compresses everything into 0.5–0.9, so it
   can't. This is documented in DECISIONS §3 rather than hidden.
